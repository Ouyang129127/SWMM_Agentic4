# M6：前期状态—峰间退水—本次冒溢（2026-11-15）

新诊断任务在整场雨情之外，直接提供目标节点及已声明局部连接范围的前期水力记录。M6调查先查前期状态与退水，再连接本次来水和冒溢过程。

## 进入LLM的实际信息

- 整场实际雨强序列及各事件的雨峰、雨段、间歇时间定位，维持原有输入。
- 原生输出中相关节点的水深、水头、实际储量、总入流、侧向入流和冒溢流量；管段的水深、实际储量及有符号流量。
- 每个目标节点一份`antecedent_hydraulic_context`，从最早保存时刻延伸至其相关事件中最晚的起溢时刻。同节点多个事件共用，避免重复发送相同历史。
- 每个`event_context.antecedent_hydraulics`给出共享证据ID和本事件`event_cutoff`。判断前期状态时只读取该起溢时刻及之前的样本；本次冒溢过程仍读本事件`local_process_series`。

前期背景默认每300秒选取实际保存样本，同时保留雨峰、雨段起止、相关事件起止/峰时两侧的实际样本，不插值；原保存步长更粗时按实际覆盖说明。冒溢窗口保持原保存分辨率。原生输出最早时刻也显式保留；它不冒充模拟零时刻，输入初始设置和热启动条件仍需分别核实。

稀疏背景用于定位前期占水、退水和再次增长的区段。若关键变化落在采样点之间，LLM应以`saved_result_extract`针对明确对象和起止时刻申请`local_process_series`或`storage_volume_process`，补取该段原保存分辨率的数据。已有低频样本之间的变化保持未知，不能当作没有变化。

## 来源、选择与引用

只读统一证据包已绑定哈希的`swmm/model_with_event.inp`和`swmm/model.out`。准备前和提取后复核哈希；同次任务对相关对象的原生输出只读取一次。缺文件、缺来源绑定或单位不受支持时，事件中显式记录前期历史不可用，不填零、不宣称排空。

空间范围沿用所选事件已有的局部结构。全场任务提供各目标节点的历史；节点/事件追问只准备其相关历史。记录在任务快照内生成，旧证据包、历史诊断及模拟结果不改动。

共享历史没有单一event_id，相关事件通过自身event_context引用它；逐事件判断仍须引用本事件的事实/结构/过程记录。原有对象及事件绑定校验继续生效。

`path_table_v1`表格传输适用于新历史记录，完整保留其已明确选取的样本、字段、数值和引用。原事件目录的六组证据不增删，前期水力为任务级补充上下文，协议仍为joint_mechanisms_v2。
